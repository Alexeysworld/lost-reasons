# Runbook: как обработать xlsx с проигранными сделками

На вход — xlsx как апрельский (колонки `Deal - ID`, `Deal - Причина проигрыша`,
`Deal - Коммент при проигрыше Midmarket`, `Deal - Конкурент…` и т.д.).
На выход — тот же xlsx + 4 колонки (см. `docs/methodology.md` §5).

Классификацию делает агент (Claude) с доступом к Pipedrive MCP — «интеллект» в
рассуждении по каждой сделке, а скрипты отвечают только за ввод/вывод и за
выжимку из заметок.

## Шаги

1. **Прочитать вход в JSON**
   ```bash
   python scripts/xlsx_io.py read input.xlsx data/input.json
   ```

2. **По каждой сделке собрать контекст из Pipedrive** (агент, через MCP):
   - поле `Коммент при проигрыше` и `Конкурент…` уже есть во входном xlsx;
   - заметки: `mcp__pipedrive__get_notes(deal_id=<id>)` → сохранить дамп в
     `data/notes/<id>.json` → выжимка:
     ```bash
     python scripts/notes_digest.py data/notes/<id>.json
     ```
     (показывает internal-комментарии менеджера, блоки «Прогноз/Что тормозит»
     из «Оценки встречи», прячет автозаметки и транскрипции);
   - при необходимости `get_deal` для доп. полей.

3. **Классифицировать** по дереву решений `docs/methodology.md` §4:
   определить категорию, детализацию (имя конкурента / модуль интеграции),
   написать обоснование со ссылкой на источник и уверенность.

4. **Собрать результат** в `data/classifications.json`
   (`{ "<deal_id>": {real_reason, detail, rationale, confidence}, ... }`) и записать:
   ```bash
   python scripts/xlsx_io.py write input.xlsx data/classifications.json output/result.xlsx
   ```

5. **(Если есть эталон)** сверить с колонкой «Реальная причина» для оценки точности.

## Замечания

- Доверять полю `Причина проигрыша` нельзя (см. §1 методологии). Категориям
  «не могу получить ответ» и «SS» — почти всегда можно.
- При конфликте сигналов берём самый поздний по времени и самый конкретный.
- Если данных нет — оставляем указанную причину и `confidence: low`.
- Pipedrive доступен только агенту (MCP), не самим скриптам, — токена в окружении нет.
