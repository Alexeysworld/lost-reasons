# Lost reasons: реальная причина проигрыша Midmarket

Цель: для проигранных сделок определить **реальную** причину (не доверяя формальному
полю «Причина проигрыша») и вернуть xlsx с колонками: реальная причина, детализация
(конкретный конкурент X / модуль интеграции Y), обоснование, уверенность.

Вся логика классификации — в `docs/methodology.md`. Справочник по Pipedrive (id
фильтров, поля, условия) — в `docs/pipedrive_reference.md`. Этот файл — оркестрация.

## Когда источник — Pipedrive (xlsx не нужен)

Это режим по умолчанию, если пользователь называет период/сегмент, а не присылает файл.

1. **Определи период и срез.** По умолчанию — «Midmarket-проигрыши после встречи»
   (pipeline 53 + дошли до этапа 385 + проиграны в периоде). Период — из запроса
   («за май», «прошлый месяц», «последние 4 месяца»).

2. **Получи фильтр** (любой вариант):
   - переиспользовать готовый: `get_filter(153211)` (прошлый месяц), `47454`
     (4 месяца после встречи), `122763` (текущий месяц) — см. справочник;
   - или создать свой под период: `create_filter(type="deals", name=..., conditions=...)`
     с условиями из `docs/pipedrive_reference.md` (подставь нужное значение `lost_time`:
     `last_month` / `this_month` / `N_months_ago` / дата). Сохрани вернувшийся `id`.

3. **Вытяни сделки**: `get_deals(filter_id=<id>, limit=100)`, листай по
   `additional_data.next_cursor`, пока не кончатся. Сохрани все страницы в один
   JSON-массив `data/deals_dump.json`.

4. **Преобразуй в вход**:
   `python scripts/deals_to_input.py data/deals_dump.json data/input.json`
   (раскладывает custom_fields по именованным колонкам через карту кодов из справочника).

5. Переходи к блоку **«Классификация»**.

## Когда источник — xlsx

Пользователь прислал файл (как апрель/май).
`python scripts/xlsx_io.py read input.xlsx data/input.json` → блок «Классификация».

## Классификация (общая часть)

Для каждой сделки из `data/input.json`:

1. Уже есть из шага выгрузки/файла: коммент при проигрыше, поле «Конкурент», цели,
   сильные/слабые стороны, указанная причина.
2. Подними заметки: `get_notes(deal_id=<id>)` → сохрани в `data/notes/<id>.json` →
   `python scripts/notes_digest.py data/notes/<id>.json` (выжимка: internal-комменты
   менеджера + блоки «Прогноз/Что тормозит» из «Оценки встречи», без шума).
   Заметки тяни прежде всего для сделок, где коммент пуст/неоднозначен (это и есть
   `confidence: low/medium`). Большие транскрипции читать только при необходимости.
3. Классифицируй по дереву решений `docs/methodology.md §4`: категория + детализация
   (имя конкурента / модуль) + обоснование (источник + дословная зацепка) + уверенность.
4. Собери `data/classifications.json`:
   `{ "<deal_id>": {real_reason, detail, rationale, confidence}, ... }`.

## Сборка ответа

- Pipedrive-вход (без исходного xlsx):
  `python scripts/xlsx_io.py write-from-json data/input.json data/classifications.json output/result.xlsx`
- xlsx-вход:
  `python scripts/xlsx_io.py write input.xlsx data/classifications.json output/result.xlsx`

Отдай `output/result.xlsx` пользователю (SendUserFile). При наличии эталонной колонки
«Реальная причина» — посчитай и приведи точность.

## Правила классификации (полностью; примеры — docs/methodology.md)

**Базовое:** полю «Причина проигрыша» не верь — оно формальное. Доверяй ему только для
«не могу получить ответ» (→ Клиент перестал отвечать) и «SS». Остальное выводи из
коммента при проигрыше + поля «Конкурент» + заметок (особенно блоки «Что тормозит /
Прогноз» в «Оценке встречи» и свежие internal-комменты у даты проигрыша).
При конфликте сигналов — самый **поздний** по времени и самый **конкретный**.

**Глоссарий (важно!): ЛПР ≠ ЛВР.**
- **ЛПР** — руководитель и *бюджетодержатель* (директор/собственник/гендир), финальное
  решение и деньги.
- **ЛВР** — лицо, лишь *влияющее* на решение (маркетолог/специалист), без бюджета.

**Дерево решений (по порядку, первая сработавшая ветка побеждает):**
0. **Вето ЛПР — приоритетно.** Зарубил руководитель/собственник/бюджетодержатель
   («собственница не согласовала», «не приоритет у ГД», «тугой ЛПР, денег жалко»)
   → **Руководитель заблокировал решение** — даже если есть текущий стек/конкурент.
1. Назван конкретный конкурент/стек и причина — остаться на нём / выбрать / делать сами
   (и НЕ было вето ЛПР) → **Конкурент** (детализация = **имя**).
2. Не наша ЦА (маркетплейсы, колл-центр, тендерный подрядчик, банкрот) → **Нецелевой**
   (формулировки «Нецелевые» и «Нецелевая встреча» = то же самое, сводим сюда).
3. Маленькая база / self-service → **SS** (укажи базу, если есть).
4. Экономика не сходится («не окупаемся», «слабые цифры», «малыши», низкая маржа) →
   **Не окупаемся** (это про арифметику ROI, не про «дорого при норм базе»).
5. Цена/бюджет — стоп при нормальной базе («дорого», «порезали бюджеты», «оптимизируют
   расходы») → **Клиенту дорого, хотя база норм**.
6. Блокер — интеграция/разработка → **Интеграция** + подтип (детализация = **модуль/что**):
   нет коннектора с системой Y (YClients, ЦФТ, ARORA, Intickets, MobiFitness, Киноплан…);
   сложная/кастомная (МИС, BeautyExpert); идёт разработка (сайт/приложение/1С/Битрикс);
   поставщик заблокировал интеграцию.
7. Некому вести платформу / нет маркетолога (сама интеграция не главный стоп) →
   **Нет ресурса маркетинга**.
8. Контакт/чемпион ушёл из компании → **Уволился наш контакт**.
9. **Гендир/ЛПР не зажёгся/зарубил** — разводим по присутствию на ПЕРВОЙ встрече
   (поле «Участники первой встречи»): был на встрече и не зажёгся → **Не заинтересовали
   гендира на первой встрече**; не было, зарубил заочно/не дал бюджет/«польза упала в
   глазах ЛПР» → **Руководитель заблокировал решение** (= п.0).
9b. Встреча прошла, **ЛВР** (не бюджетодержатель) отвечает отбивками/вяло («пауза»,
   «на холде», «морозятся») → **Не заинтересовали ЛВР**.
10. Просят вернуться позже (реорг, «сейчас не приоритет», конкретный срок) →
    **Попросили отложить**.
11. Просто пропал, контента нет → **Клиент перестал отвечать** (+ на каком шаге пропал).

Если данных нет вообще — берём указанную причину как есть, `confidence: low`.

**Уточнения (подтверждены заказчиком):**
- Таксономия зависит от периода: «Не окупаемся» и «Уволился наш контакт» появились ~в мае;
  в более ранних месяцах их сворачивали в SS / дорого / перестал отвечать. Сверяясь с
  конкретным месяцем — используй набор категорий того месяца.
- **SS vs цена/окупаемость (тай-брейкер):** если **указанная причина = SS** → оставляем
  **SS**. Если указана другая причина, а в комменте «нет бюджета / порезали-заморозили
  бюджеты / посчитали окупаемость и не окупается» → **«Клиенту дорого, хотя база норм»**.
  (Т.е. «не окупается» = «дорого, хотя база норм»; отдельная «Не окупаемся» — только если
  есть в наборе категорий месяца, напр. май.) SS — про размер, не про деньги.
- «Хватает своих инструментов / свой стек закрывает / назван стек, на котором остаются» =
  **Конкурент**, даже если упомянуты «не окупаемся» или просьба отложить. (Стек не назван,
  стоп — арифметика → «Не окупаемся».)
- **Ответ часто в Notes, а не в комменте при проигрыше — заметки перевешивают** (заморожен
  бюджет → дорого; синк через N мес → отложить; «польза упала в глазах ЛПР» → руководитель).
- Эталон бывает с ошибками — их тоже подсвечивай.

**Обязательная детализация:** Конкурент → имя конкурента/стека; Интеграция → модуль/подтип.

**Создание фильтра** — это запись в CRM пользователя: делай осознанно (имя вида
`[auto] Midmarket проигрыши <период>`), по возможности переиспользуй существующий.
