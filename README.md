# lost-reasons

Автоматизированное определение **реальной** причины проигрыша в Midmarket-сделках
Mindbox. Консультанты заполняют поле `Причина проигрыша` формально, поэтому
реальную причину приходится восстанавливать вручную из комментариев и заметок
Pipedrive. Этот репозиторий описывает методологию и инструменты, чтобы делать это
воспроизводимо.

## Что внутри

- **`docs/methodology.md`** — ядро: почему нельзя верить указанной причине,
  таксономия реальных причин, приоритет источников, дерево решений, формат вывода.
- **`docs/runbook.md`** — пошаговый процесс обработки xlsx.
- **`scripts/xlsx_io.py`** — чтение входного xlsx и запись результата с 4 добавленными
  колонками (`Реальная причина (авто)`, `Детализация`, `Обоснование`, `Уверенность`).
- **`scripts/notes_digest.py`** — выжимка из дампа заметок Pipedrive
  (комментарии менеджера + блоки «Прогноз/Что тормозит», без шума).
- **`data/april_2026.json`** — эталонный размеченный набор за апрель (92 сделки).
- **`output/april_demo_result.xlsx`** — демонстрация формата на 8 перепроверенных
  через Pipedrive сделках.

## Результаты калибровки

**Апрель (8 сделок, перепроверены через Pipedrive вслепую):** 7/8 совпадений по
категории. Расхождение — сделка 369166 (в заметках нет сигнала о цене), помечено
для ручной проверки.

**Май (90 сделок, два прогона):**
- *Только дешёвые сигналы* (коммент при проигрыше + поле «Конкурент» + указанная
  причина, без заметок): **72/90 = 80%**; на сделках с `confidence=high` — **28/30 = 93%**.
- 16 из 18 ошибок — это `confidence=low/medium`, т.е. ровно те, где методология
  требует поднять заметки.
- *После заметок* по 4 флагнутым сделкам (356628 «уволился контакт», 372865 «ARORA»,
  333995 и 370601 «SS»): **76/90 = 84%**. Остаток ошибок — пограничные суждения
  («дорого» vs «не окупаемся», «отложить» vs «перестал отвечать») и пара
  несостыковок в самом эталоне (356900: коммент «не окупаемся», а размечено «Интеграция»).

Вывод: дешёвые сигналы дают 80% «из коробки», `confidence` корректно изолирует
сложные кейсы, а подъём заметок по low/medium докручивает точность. Полный прогон с
заметками по всем low/medium ожидаемо даст ~90%+.

Файлы результатов: `output/april_demo_result.xlsx`, `output/may_2026_result.xlsx`.

## Как запустить

См. `docs/runbook.md`. Кратко: `xlsx → read → (агент собирает Pipedrive-контекст и
классифицирует по методологии) → write → result.xlsx`.
